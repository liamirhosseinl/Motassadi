# سامانهٔ املاک متصدی

وب‌سایت عمومی و پنل مدیریت دفتر **املاک متصدی** (زرند): معرفی و جست‌وجوی ملک، ثبت درخواست مشتری، مدیریت مخاطبان و پیگیری‌ها، معاملات و کمیسیون، دریافت و هزینه، گزارش‌ها و خروجی CSV.

> این سند برای کسی است که سامانه را نصب، راه‌اندازی و نگهداری می‌کند. راهنمای استقرار کامل سرور در [`docs/deployment.md`](docs/deployment.md) آمده است.

## فناوری‌ها

| بخش | ابزار |
|---|---|
| چارچوب | Next.js 15 (App Router) + React 19 + TypeScript |
| پایگاه داده | PostgreSQL (تولید) — PGlite (اجرای محلی و آزمون، بدون نصب PostgreSQL) |
| ORM و مهاجرت | Drizzle ORM / drizzle-kit — فایل‌های SQL در `drizzle/` |
| اعتبارسنجی | zod (همهٔ ورودی‌ها روی سرور) |
| تصویر | sharp — تغییر اندازه، WebP، حذف متادیتا (از جمله موقعیت GPS) |
| آزمون | Vitest (سرویس‌ها) + Playwright (مسیرهای کاربر، خارج از مخزن) |

نیازمندی: **Node.js 20.9 یا بالاتر** (روی Node 22 آزموده شد).

## راه‌اندازی محلی

```bash
npm ci
cp .env.example .env            # مقادیر را بازبینی کنید
npm run db:migrate              # ساخت جدول‌ها و داده‌های پایه (دسته‌ها، دسترسی‌ها، صفحات)
npm run admin:create -- --username amir --name "نام کامل"
npm run dev                     # http://localhost:3000  — پنل: http://localhost:3000/admin
```

با تنظیم پیش‌فرض `DATABASE_URL=pglite://./.data/db` پایگاه داده داخل پوشهٔ `.data` ساخته می‌شود و نیازی به نصب PostgreSQL نیست.

> **PGlite فقط یک پردازش هم‌زمان را می‌پذیرد.** پیش از اجرای اسکریپت‌ها (`admin:create`، `db:migrate`، `seed:demo`) سرور را متوقف کنید. برای تولید از PostgreSQL استفاده کنید.

## متغیرهای محیطی

| نام | الزامی | توضیح |
|---|---|---|
| `DATABASE_URL` | بله | `postgres://user:pass@host:5432/db` یا `pglite://<مسیر>` |
| `SITE_URL` | بله | نشانی عمومی سایت بدون `/` انتهایی؛ برای sitemap، canonical، robots و داده‌های ساختاریافته |
| `UPLOAD_DIR` | بله | پوشهٔ عکس‌ها و رسیدها؛ باید روی دیسک پایدار و در برنامهٔ پشتیبان باشد |
| `SESSION_TTL_HOURS` | خیر | مدت اعتبار نشست ورود؛ پیش‌فرض ۱۲ ساعت (با هر استفاده تمدید می‌شود) |
| `COOKIE_SECURE` | خیر | اگر تنظیم نشود در production برابر `true` است. فقط برای آزمایش محلی روی http مقدار `false` بدهید |
| `DB_POOL_MAX` | خیر | حداکثر اتصال به PostgreSQL؛ پیش‌فرض ۱۰ |
| `ADMIN_PASSWORD` | خیر | فقط برای اجرای غیرتعاملی `admin:create`؛ پس از استفاده پاکش کنید |

هیچ رمز یا کلید واقعی در مخزن نیست. فایل `.env` در `.gitignore` است.

## پایگاه داده و مهاجرت

- طرح پایگاه داده: `src/server/db/schema.ts`
- مهاجرت‌ها: `drizzle/*.sql` (تولیدشده با `npm run db:generate` پس از تغییر طرح)
- اجرا: `npm run db:migrate` — مهاجرت‌ها را اعمال و داده‌های پایه را (فقط اگر نباشند) اضافه می‌کند. اجرای دوباره بی‌خطر است.
- اتصال PGlite هنگام باز شدن خودش مهاجرت را اجرا می‌کند.

داده‌های پایه: دسترسی‌های پیش‌فرض نقش‌ها، ۷ نوع ملک، ۱۶ امکان ملک، دسته‌های مالی (از جمله «کمیسیون فروش/اجاره» و «استرداد یا تعدیل کمیسیون»)، صفحات محتوایی پیش‌نویس و تنظیمات کسب‌وکار از اطلاعات تأییدشده (نام، مدیر، نشانی، تلفن ۰۹۱۳۶۱۸۹۸۰۸).

## ساخت نخستین مدیر و بازیابی رمز

هیچ رمز پیش‌فرض و هیچ ثبت‌نام عمومی وجود ندارد.

```bash
# ساخت نخستین مدیر (رمز به‌صورت پنهان پرسیده می‌شود)
npm run admin:create -- --username amir --name "فرج‌الله متصدی زرندی"

# بازیابی: مدیر رمزش را فراموش کرده یا حسابش قفل شده
npm run admin:create -- --reset-password --username amir
```

- رمز دست‌کم ۱۰ نویسه و نه فقط عدد.
- اگر مدیر فعالی وجود داشته باشد، ساخت مدیر جدید از خط فرمان رد می‌شود (مگر با `--allow-additional`)؛ کاربران دیگر را از پنل «کاربران و دسترسی» بسازید.
- بازیابی رمز، قفل حساب را باز می‌کند و همهٔ نشست‌های قبلی آن کاربر را می‌بندد.
- اجرای غیرتعاملی: `ADMIN_PASSWORD='...' npm run admin:create -- ...` (سپس متغیر را از محیط و تاریخچهٔ شل پاک کنید).

## دادهٔ نمونه (فقط محیط توسعه)

```bash
npm run seed:demo
```

۲۰ آگهی در همهٔ نوع‌ها (آپارتمان، خانهٔ ویلایی، ویلا، زمین، باغ، مغازه؛ فروش، اجاره، رهن و معاوضه) با ۶۹ تصویر می‌سازد: ۱۶ منتشرشده، یک رزروشده، یک فروخته‌شده، یک پیش‌نویس و یک «در انتظار بررسی». به‌علاوه ۶ مخاطب، ۵ درخواست، ۳ پیگیری (یکی عقب‌افتاده)، دو معامله (یکی تسویه‌شده، یکی با کمیسیون ناقص) و ثبت‌های دریافت و هزینهٔ چهار ماه اخیر، تا داشبورد و گزارش‌ها هم پر دیده شوند.

همهٔ عنوان‌ها و نام مخاطبان با «نمونه —» شروع می‌شوند، شماره‌ها ساختگی‌اند (`0900…`)، نام محله‌ها ساختگی است و عکس‌ها تصاویر آزاد Unsplash‌اند (`scripts/demo-photos/`، فهرست منبع و عکاس در `docs/photo-credits.md`) — عکس خود این املاک نیستند و از آگهی‌های واقعی سایت‌های دیگر هم برداشته نشده‌اند. توضیح هر آگهی هم یک خط هشدار «آگهی نمونه» دارد. اسکریپت:
- با `NODE_ENV=production` اجرا نمی‌شود؛
- روی PostgreSQL فقط با `--allow-postgres` اجرا می‌شود؛
- روی پایگاه دادهٔ غیرخالی اجرا نمی‌شود.

**هرگز روی پایگاه دادهٔ واقعی دفتر اجرا نکنید.**

## آزمون‌ها و کیفیت کد

```bash
npm run typecheck
npm run lint
npm test                        # روی PGlite در حافظه
TEST_DATABASE_URL=postgres://... npm test   # روی PostgreSQL واقعی — پایگاه داده‌ای مهاجرت‌شده که فقط برای آزمون است؛ پیش از هر فایل آزمون همهٔ جدول‌ها خالی می‌شوند
```

مسیرهای کامل کاربر در مرورگر (سایت عمومی، ورود، درخواست، آگهی و عکس، معامله و کمیسیون، ابطال، گزارش، تنظیمات، کاربران، محدودیت نقش مشاور، نمای موبایل) با Playwright روی یک build تولیدیِ در حال اجرا و پایگاه دادهٔ **یک‌بارمصرف**:

```bash
E2E_BASE_URL=http://localhost:3100 E2E_OWNER_PASSWORD='...' node tests/e2e/journeys.cjs
```

آزمون‌های واحد و سرویس چرخهٔ عمر آگهی، دسترسی نقش‌ها، ورود و قفل حساب، جست‌وجوی عمومی، درخواست و ضداسپم، مخاطب و پیگیری، معامله و کمیسیون، ابطال ثبت مالی، گزارش‌ها، خروجی CSV، تنظیمات و کاربران را پوشش می‌دهند.

## ساخت نسخهٔ تولیدی

```bash
npm run build                   # next build + آماده‌سازی .next/standalone
npm run start:standalone        # node .next/standalone/server.js
```

`npm run build` پوشه‌های `public/`، `.next/static/` و `drizzle/` را داخل `.next/standalone` کپی می‌کند. سرور standalone پوشهٔ کاری را به `.next/standalone` تغییر می‌دهد، پس **در سرور برای `UPLOAD_DIR` و مسیر PGlite نشانی مطلق بدهید.** متغیرها را از محیط سرویس (مثلاً systemd) بدهید. جزئیات: [`docs/deployment.md`](docs/deployment.md).

## جست‌وجو و گزارش‌ها

- **جست‌وجوی سراسری پنل** (کادر بالای منو یا `/admin/search`): کد ملک، عنوان، نام، شماره تلفن، کد معامله و شمارهٔ مرجع ثبت مالی را هم‌زمان در املاک، مخاطبان، درخواست‌ها، معاملات و دریافت/هزینه می‌گردد. هر بخش با همان قواعد دسترسی صفحهٔ خودش جست‌وجو می‌شود؛ بخشی که کاربر به آن دسترسی ندارد اصلاً نمایش داده نمی‌شود و مشاور فقط آگهی‌ها و درخواست‌های خودش (و بدون مسئول) را می‌بیند.
- **سایت عمومی:** نتایج جست‌وجو به دو شکل شبکه‌ای و فهرستی (`view=list`) نمایش داده می‌شود؛ نحوهٔ نمایش با فیلترها حفظ می‌شود.
- **گزارش مالی:** جمع بازهٔ انتخابی، تفکیک دسته‌ها، نمودار شش ماه اخیر، جدول ماه‌به‌ماه سال شمسی جاری با جمع سال، خلاصهٔ سه سال اخیر و مطالبات کمیسیون.

## نقش‌ها و دسترسی‌ها

| نقش | کار پیش‌فرض |
|---|---|
| مدیر / مالک | همه‌چیز؛ تنها نقشی که معاملهٔ بسته را بازگشایی می‌کند |
| مشاور | آگهی‌های خودش (پیش‌نویس و ارسال برای بررسی، بدون انتشار)، درخواست‌های خودش و بدون مسئول، مخاطبان، پیگیری، مشاهده و ثبت معامله |
| مالی | معاملات، دریافت و هزینه، ابطال، گزارش مالی، خروجی CSV |
| مدیر محتوا | آگهی‌ها و انتشار، صفحات و سئو |

دسترسی هر نقش از «کاربران و دسترسی» قابل تغییر است. همهٔ بررسی‌ها روی سرور انجام می‌شود (صفحه، اکشن، مسیر API، خروجی). دسترسی‌های «مدیریت کاربران»، «تنظیمات» و «داشبورد» برای نقش مدیر قفل است و آخرین مدیر فعال قابل غیرفعال‌کردن یا تغییر نقش نیست.

## قواعد مالی

- همهٔ مبالغ **عدد صحیح تومان** ذخیره می‌شوند. واحد نمایش در سایت از تنظیمات قابل تغییر به ریال است (ریال = تومان × ۱۰). فرم‌های پنل همیشه به تومان‌اند و برچسب دارند.
- **ارزش ملک یا مبلغ معامله درآمد دفتر نیست.** درآمد دفتر فقط از ثبت‌های «دریافت» بخش مالی می‌آید.
- کمیسیون مورد انتظار روی سرور از روش محاسبه (مبلغ ثابت یا درصد از ارزش معامله) حساب می‌شود؛ کمیسیون دریافتی = جمع دریافت‌های دستهٔ کمیسیون منهای استردادها.
- ثبت مالی **حذف نمی‌شود**؛ با ذکر دلیل «باطل» می‌شود، از جمع‌ها خارج می‌شود و در گزارش رویدادها می‌ماند.
- تاریخ آینده، مبلغ صفر و دسته‌ای که با نوع ثبت نمی‌خواند پذیرفته نمی‌شود. فرم ثبت کلید یکتا دارد تا دوبار زدن دکمه ثبت تکراری نسازد.
- معاملهٔ تکمیل‌شده یا لغوشده قفل است؛ بازگشایی فقط توسط مدیر و با دلیل.
- سامانه نرخ کمیسیون قانونی را تعیین نمی‌کند؛ نرخ را دفتر وارد می‌کند.

## امنیت

- رمزها با scrypt و نمک تصادفی؛ مقایسهٔ زمان‌ثابت.
- نشست: توکن تصادفی ۳۲ بایتی در کوکی `httpOnly` و `SameSite=Lax` (و `Secure` در تولید)؛ در پایگاه داده فقط هش SHA-256 آن ذخیره می‌شود. تغییر رمز همهٔ نشست‌ها را می‌بندد.
- قفل حساب پس از ۵ ورود ناموفق برای ۱۵ دقیقه؛ محدودیت نرخ ورود به‌ازای IP؛ پیام خطای ورود عمومی است.
- فرم درخواست عمومی: فیلد تله، حداقل زمان پر کردن، محدودیت نرخ به‌ازای IP و شماره، رضایت صریح.
- بررسی Origin برای مسیرهای API نوشتنی؛ اکشن‌های سرور Next.js محافظت CSRF داخلی دارند.
- سرآیندهای امنیتی (CSP پایه، `X-Frame-Options`، `Referrer-Policy`، `X-Content-Type-Options`، `Permissions-Policy`)؛ پنل `noindex` و `no-store`.
- نشانی دقیق ملک، یادداشت داخلی، مالک و مشاور هرگز به صفحات عمومی، JSON-LD یا خروجی عمومی نمی‌رسد (فهرست سفید فیلدها).
- عکس‌ها با نام تصادفی ذخیره می‌شوند و فقط وقتی ملک عمومی است از `/media` قابل دریافت‌اند. پیوست‌های مالی فقط برای کاربر دارای دسترسی و با `Content-Disposition: attachment`.
- خروجی CSV با BOM و خنثی‌سازی فرمول (`= + - @`)؛ هر خروجی در گزارش رویدادها ثبت می‌شود.

## پشتیبان‌گیری و بازگردانی

دو چیز باید پشتیبان داشته باشد: **پایگاه داده** و **پوشهٔ `UPLOAD_DIR`**.

```bash
# PostgreSQL — پشتیبان روزانه
pg_dump --format=custom --file=/backup/motasadi-$(date +%F).dump "$DATABASE_URL"
tar -czf /backup/uploads-$(date +%F).tar.gz -C /var/lib/motasadi uploads

# بازگردانی (روی پایگاه دادهٔ خالی)
pg_restore --clean --if-exists --no-owner --dbname="$DATABASE_URL" /backup/motasadi-2026-10-31.dump
tar -xzf /backup/uploads-2026-10-31.tar.gz -C /var/lib/motasadi
```

PGlite: سرور را متوقف کنید و کل پوشهٔ داده (مثلاً `.data/db`) را کپی کنید.

پشتیبان‌ها را بیرون از همان سرور نگه دارید و دست‌کم ماهی یک بار بازگردانی را روی محیط آزمایشی امتحان کنید.

## فونت و هویت بصری

- رنگ‌ها، نشانه و قواعد تایپوگرافی از کتاب برند «املاک متصدی» گرفته شده و در `src/app/globals.css` (توکن‌ها) و `public/brand/` است.
- نظام حروف: **لحظه** فقط برای تیترهای نمایشی (Display)، **ایران‌سنس X** برای متن و رابط کاربری، و **ایران‌یکان (ارقام فارسی)** برای اعداد و قیمت‌ها. فایل‌های ایران‌سنس X و ایران‌یکان هم از پوشهٔ فونتی که دفتر داد به WOFF2 تبدیل شده‌اند؛ این دو هم فونت تجاری‌اند و مجوز وبشان باید پیش از انتشار تأیید شود.
- عکس‌های صفحهٔ اصلی و دسته‌ها در `public/images/site/` از Unsplash هستند (فهرست در `docs/photo-credits.md`). برای سایت واقعی بهتر است با عکس املاک خود دفتر جایگزین شوند؛ اگر فایلی حذف شود، بخش مربوط بدون عکس و با رنگ برند نمایش داده می‌شود.
- فونت **لحظه (Lahzeh)**، طراحی حسین حیدری، از فایل‌هایی که دفتر در اختیار گذاشت به WOFF2 تبدیل و در `public/fonts/` قرار گرفت. طبق متن خود فایل فونت، این قلم تجاری است و مجوز آن از fontiran.com تهیه می‌شود. **پیش از انتشار عمومی سایت، مجوز استفادهٔ وب (web embedding) را بخرید یا تأیید کنید.** اگر مجوز نبود، فقط کافی است فایل‌ها و `@font-face` را با فونت دیگری جایگزین کنید؛ بقیهٔ طراحی تغییر نمی‌کند.
